Identity & Access Management Configuration

Configure OpenID Connect Single Sign-On (SSO), OData v4 Bearer Token Protection, and OAuth 2.0 API Authorization Server policies.

1. Authentication & Authorization Modes Security Policy

Control how authentication is enforced for Web UI interactive sessions and OData v4 programmatic API consumers.

Use OIDC for Web Interface Disabled
When enabled, navigating to the HR System Web UI displays the SSO Welcome Gate screen, requiring users to authenticate via the OpenID Connect Identity Provider (IdP) before viewing, creating, or modifying HR records. If disabled, direct lab access is permitted.
Use OIDC / OAuth 2.0 Bearer for OData v4 API Disabled
When enabled, all OData v4 endpoints (/odata/*) require a valid Bearer JWT access token in the Authorization: Bearer <token> HTTP header (or an active authenticated SSO cookie session). Unauthenticated API requests receive HTTP 401 Unauthorized.

Select how authorization is evaluated once an identity token has been verified.

Any user or API client presenting a valid token or session from the configured OpenID Provider is granted full access to perform all Read and Write operations (GET, POST, PUT, PATCH, DELETE). Scopes and audiences are not strictly enforced.
Enforces OAuth 2.0 Authorization Server rules: verifies the token contains the configured Audience (aud), requires the Read Scope (hr:read) for GET, requires the Write Scope (hr:write) for mutations (POST, PUT, PATCH, DELETE), and checks optional custom claims.
